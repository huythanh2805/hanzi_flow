# Design system

Moonlight is temporarily disabled: `AppAmbience` defaults `moonlightEnabled` to `false`, so the overlay/beam animation is not rendered and the moonlight-specific vignette mask is inactive. The landscape and card surfaces remain. Re-enable with `<AppAmbience moonlightEnabled />` in the root layout.

Original references: `01-welcome.png` through `16-settings.png` from the supplied HanziFlow-UI-Images directory. The 2026-10-25 `HanziFlow-Design-Handoff` established the dark Flashcards screen and shared sidebar/shell: `01-references/redesigned-ui.png`, typography/color/layout tokens, component specifications and interactions. Read from the owner's Downloads folder; no reference screenshot is shipped as a UI asset or background substitute.

Light mode retains the cool off-white canvas, white cards and jade controls. The owner subsequently requested that the moonlit Flashcards visual language apply throughout the app. `brand-theme.css` now owns shared root tokens: canvas `#05080A`, panels `#0B1213` / `#10191A`, text `#F2F7F4`, muted text `#9FB4AA`, mint `#63F2B1`, emerald `#35C98B` and translucent mint borders. Gradients are limited to progress, CTA, the card's subtle highlight and background fading. The owner-supplied moonlit valley image sits behind a dark vignette; glass panels use restrained transparency, 12px panel / 16px Flashcard backdrop blur and soft shadows. Next Image provides responsive optimization and a blur placeholder. The scene is decorative, noninteractive and excluded from assistive technology; unsupported backdrop blur falls back to a more opaque panel. No additional package or font dependencies.

Shared typography is a rem-based scale: captions 12px, supporting labels 13–14px, navigation/buttons 15px, body/Vietnamese definitions 16–18px at the default browser text size. Small legacy 7–12px declarations map to that scale in `globals.css`, including mobile rules. Main headings range from 30–38px desktop and 27–32px mobile. UI fonts remain Inter/Segoe UI/Arial/system fallbacks with full Vietnamese diacritics; Chinese study glyphs retain local serif fallbacks and language attributes. Hanzi uses 72–112px responsive sizing; four-or-more-character entries scale down and wrap rather than clip.

`workspace.css` owns shared shell/study layout refinements; `brand-theme.css` loads afterward with shared visual tokens for color, radii, shadow, blur and spacing. Desktop sidebar is 272px; tablet is 252px (768–1199); mobile (≤767) uses a 288px drawer constrained to viewport width. The JS media query and CSS breakpoint match. Main container is capped at 1276px including padding (1180px content). The study row maxes at 960px including 48px navigation controls, producing an ~832px card. Study cards have 24px radii, at least 420px desktop/360px mobile height, and grow for expanded definitions. CTA max-width is 600px with 54px height. On narrower screens navigation arrows move below the card so labels/buttons remain readable.

`AppSidebar` owns shared navigation presentation. Controlled study components live in `src/components/flashcards/`: `FlashcardsHeader`, `StudyProgress`, `StudyToolbar`, `FlashcardPanel`, `FlashcardActions`, `ShortcutHints`. Shared `src/components/app-ambience.tsx` exports `AppAmbience` (mounted once in the root layout), `SidebarAmbience` and `SceneArtwork` for dashboard/welcome/auth illustrations. The existing `Flashcards` controller retains session selection, keyboard behavior, autoplay, shuffle and progress mutations; presentation components receive values and callbacks. Asset provenance is recorded in `public/images/README.md`.

Desktop retains persistent navigation and a quiet utility bar; the study shell uses compact top spacing to keep its CTA visible at 1440×900. Mobile retains the focus-trapped drawer, backdrop, Escape dismissal and focus restoration. Native buttons, ≥44px study controls, visible focus, semantic progress values, status announcements and reduced-motion support remain. The native card-background button flips the card without nesting the speaker/detail buttons; actionable child controls keep independent hit targets. Modifier keys, repeated keydown and IME composition are ignored by study shortcuts, as are input/select/textarea/contentEditable and focused buttons/links. Existing learning, audio, autoplay, shuffle, favorites and persistence use the original state/actions.

Public pages default to the dark brand theme; the existing application theme preference still controls light/dark/system inside the learning workspace. Dark and light themes share geometry and typography. The dashboard, vocabulary tables/details, Band/topic catalogues and lessons, settings, roadmap, welcome, login, documentation, loading and error screens inherit the same root palette and backdrop.

`lighting.css` adds dark-mode lighting without changing geometry. `MoonlightOverlay` sits between the shared scene (z-index 0) and vignette (2), below all application content; three low-opacity radial gradients and a blurred diagonal beam diffuse mint/emerald light from the top-right. A 20-second opacity/scale cycle gives slow breathing. Flashcards retain their glass surface and flip transform: a masked 1px gradient ring favors the top/right edges, while a masked decorative reflection moves with opacity/transform over 11 seconds. Changing the existing revealed class restarts a 950ms edge pulse on either face, with no timers or new learning state. Fine-pointer hover gently strengthens the glow. Light mode hides these effects; reduced-motion disables all new animations, and unsupported masking retains a static directional border. All decorative layers ignore pointer events and assistive technology.

Shared dark cards and prose panels, excluding the reference Flashcard described below, retain only two soft, localized mint highlights at the center of their top and bottom edges. The masked gradient is transparent outside the middle half; its peak alpha is 42%, reduced from 98% after owner feedback. Full perimeter borders, outer glow, drop shadows and full-width inset edge highlights are removed, including on hover. Transparent 1px borders preserve geometry. Shared panels retain a restrained 12-second opacity shimmer. The bright top-right atmospheric lighting is unchanged by this card-only refinement. Reduced-motion stops these animations.

Only the main Flashcard has a landscape image inside its surface. `card-scenes.css` gives all other dark cards/prose panels a solid charcoal background; the dashboard promo and sidebar promo no longer render image elements. The page-wide landscape remains. `getImageProps` generates cached Next Image variants exposed through a root CSS `image-set` variable for the Flashcard, with a dark reading scrim and a right-biased mobile crop. Welcome/auth page illustrations remain separate from card backgrounds.

`flashcard-surface.css` loads last and applies the Flashcard's own landscape with a dark gradient overlay and a 1px emerald base border at 18% alpha. All outer/inner shadows and the bottom halo are removed; the masked accent is a radial highlight centered on the top edge, peaking at `#6EE7B7` / 65% alpha. There is no bottom-center accent, and the former traveling reflection is hidden. The existing parent flip animation, geometry, controls and focus behavior are retained. Other cards keep solid backgrounds and soft center-edge accents.

Phase 1 pages: welcome/auth, dashboard, vocabulary library/detail, HSK discovery/detail, topics discovery/detail, basic flashcards, account settings. Phase 2/3 destinations are clearly marked as planned and are not rendered as fake working pages or fake statistics.
