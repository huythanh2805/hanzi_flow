# Vocabulary practice

## Expanded activities: implemented scope and plan

Learning mode now offers **Chữ ↔ nghĩa**, **Nghe chọn chữ** and **Ghép cặp**. All three are selected initially; learners may select any nonempty subset. Exams retain the original meaning MCQ. The setup performs a read-only preflight and displays exact word counts by activity and the number of matching boards before creating a session. Empty or ambiguous selections report the affected IDs instead of silently dropping words. Each canonical vocabulary ID belongs to exactly one first-round question, regardless of activity.

Matching boards contain 2–4 compatible pairs. A singleton is redistributed into two valid boards or assigned another selected eligible type; matching-only selections that cannot form complete boards are rejected. Chinese homographs show pinyin. Mouse, touch and keyboard selection use native buttons. A wrong pair stays available to retry without revealing its correct key; the first wrong answer remains wrong in the original score, while later attempts have separate counters. Correct pairs become unavailable. Quick mode advances after the board is complete. A board is returned intact even across a 25-question batch boundary.

Listening presents a generic playback control and four Chinese choices. It does not render the prompt's Chinese/pinyin in text or accessibility labels. Answers unlock after speech starts. Mandarin voice detection waits for asynchronous browser voices, accepts mainland/Taiwan/Singapore Mandarin, and excludes Cantonese-only `zh-HK`. Replay, saved speech rate and auto-play are supported; speech cancels on navigation. Missing voices block a listening selection with installation/uncheck guidance. Playback failures do not grade an answer. Polyphonic target spellings are excluded from TTS-only prompts; distractors exclude duplicate spellings, normalized tone-equivalent readings and polyphonic spellings, preferring the same Band before lower Bands. Speech quality still depends on the installed engine; automated playback tests mock it.

The existing toolbar **Hỏi lại lượt sau** removes a matching pair from its board and queues that word's frozen meaning MCQ randomly between remaining activities. A listening question can likewise be deferred to its frozen meaning MCQ if playback becomes unavailable. The first actually answered variant determines the immutable first-round score. Changing preferences never changes the saved board, variants, choices or language. Results include first-round totals by activity and separate supplemental attempts; practice never automatically grants mastery.

Migration `202610250008_practice_exercises.sql` adds private exercise/board/fallback snapshots and answer-variant fields. Existing sessions default to meaning MCQ. A compact authenticated lexical RPC supplies all canonical entries without the REST row cap. The authenticated Server Action validates the source and builds snapshots; a **service-role-only** installation RPC writes the full recipe in one transaction with owner/request idempotency. Installation uses one bulk insert, disables per-query JIT and has a scoped 60-second RPC timeout for full-size JSON payloads; no global/role timeout changes are made. Function-specific API timeouts follow the [Supabase documentation](https://supabase.com/docs/guides/database/postgres/timeouts#function-level). The admin key stays in a `server-only` module. User-JWT commits still validate options, reject forged score fields, lock the session and grade on the database. Raw MCQ creation rejects unsupported exercise selections instead of ignoring them. Public reads hide unresolved matching keys and all exam keys/grade breakdowns until submission. Trial sessions use the same domain rules in IndexedDB, reading only the current batch and its board context during play.

Implementation order: (1) reusable frozen activity generation and validation, (2) additive database persistence and grading, (3) setup preview plus accessible activity renderers, (4) results and browser/cloud regression checks. Typing, sentence completion, sentence assembly and speech recording remain future work and are not exposed as working modes.

Routes: `/practice`, `/practice/[sessionId]`, `/practice/[sessionId]/result`. Entry points also appear on Band/topic collections and the Flashcards summary. Practice uses plain shared charcoal cards; only Flashcards have their own scene background.

Personal decks are now another source under **Từ của bạn**: select custom and/or automatic collections, union canonical IDs, then choose the complete set or multiple groups. The source and questions freeze at creation and survive source deletion. See [personal decks](decks.md). Flashcards can hand off a large frozen selection with a tab-local selection UUID instead of placing vocabulary IDs in the URL.

Choose multiple source-order groups within one Band/topic, a complete Band, or learned/favorite/difficult entries. Groups use the saved lesson size; checkboxes persist across pages and clear when changing collection or group size. Complete Bands include all canonical IDs, including unstudied entries and repeated spellings. Learning is the group default; exams are the complete-Band default. Direction defaults to mixed and meaning language to the account setting.

Every selected ID appears once. Creation validates the entire source before publishing a session. Four distinct choices come from the same Band, then lower Bands, excluding repeated spellings, labels and intersecting normalized meaning aliases. Pinyin disambiguates homograph prompts. Content snapshots retain source/sense and machine translation metadata. This is a deterministic lexical ambiguity filter, not teacher review of every dictionary gloss.

Learning commits and grades the first answer immediately and locks it. Exams allow edits, hide correctness/feedback until submission and count unanswered questions against the total score. The result separates correct, answered-wrong and unanswered counts. Marked, incorrect/unanswered or manually selected entries can form a separate child session. A child never updates its parent's score. Only explicitly saving selected entries to difficult mutates `user_vocabulary`; it does not set studied/mastered state.

**Quick mode** is an optional learning-only toggle in setup and inside the player. After a newly saved answer is confirmed correct, the player opens the next pending question immediately, including deferred words and questions in another 25-question batch. Incorrect answers stay on the feedback view. The last correct answer automatically submits the completed session and opens results; this submission keeps its own event UUID for safe retries. A failed save never advances. Disabling Quick mode keeps manual review. The presentation preference is stored in the current browser and shared between its tabs; it does not change frozen questions, grading, exam behavior or account learning progress.

In learning mode, **Hỏi lại lượt sau** is available before answering and after an incorrect answer. It advances immediately and places the word randomly anywhere later in the remaining queue, including near the end or at the tail. There is no 1–3-question limit. If other questions remain, at least one appears before the repeated word so skipping never immediately shows the same word. The event UUID chooses a stable insertion slot from all future positions, shared by the database and trial implementation. Rescheduling the same pending word moves one queued occurrence rather than duplicating it. With no other pending questions, an answered wrong word can still be practiced again; a sole unanswered question cannot be postponed without answering. The queue and current position survive reload and continue across cloud devices. A returning word is labeled **Đang hỏi lại**. **Quick mode** and the single **Hỏi lại lượt sau** action are always visible together at the top of an active learning card. There is no duplicate repeat button or helper block below the answers. The toolbar action skips immediately without requiring an answer and queues the word randomly in this session. It uses a repeat icon rather than a bookmark toggle. Exam review marking remains separate and unchanged.

Repeating an answered word clears the displayed selection/feedback and accepts a new response while retaining its original answer and first-round score. Repeated answers have their own counts in the session and are not added to the original question total. Results show first-round choices/correctness, with supplemental repeat totals separately. Quick mode waits for the whole pending queue, including repeats, before finishing automatically.

## Persistence and authorization

Migration `202610250004_practice.sql` adds sessions, immutable question snapshots, answers and idempotent events. Questions/options/language/source/lesson size are frozen. `practice_create`, `practice_read`, `practice_commit`, `practice_result_ids`, `practice_mark_difficult` and `practice_list` require the authenticated owner. Only safe session metadata can be read directly. Question keys, answers and events have RLS enabled and no direct authenticated table privileges. RPCs validate options and grade inside a transaction; client correctness fields are rejected. Exam reads never include answer keys or correct counts before submission.

Migration `202610250005_practice_defer.sql` adds the session's `deferred_ordinals` queue and extends the existing transactional commit with `defer`. It accepts only unanswered learning questions, retains request replay/revision checks and updates the resume cursor atomically. Existing sessions receive an empty queue, without changing answers, scores or catalogue/progress rows. Browser trials use the corresponding domain transition in the existing IndexedDB transaction.

Migration `202610250006_practice_interleaved_repeats.sql` extends that implementation with a persistent learning queue, pending/latest-repeat fields on answers and separate repeat counters. It initializes old sessions lazily, without rewriting their original answers. The owner-checked commit preserves locking, event replay and revision checks for both scheduling and repeat grading. A repeated event cannot duplicate the queue or grade twice. Exam responses remain secret until submission.

Migration `202610250007_practice_random_repeat_position.sql` expands insertion to all future positions using a shared unsigned 32-bit request-UUID seed. No stored queue or grade is rewritten; each new Hỏi lại request gets a newly chosen position, while retries and reloads retain the saved one.

Creation request UUIDs prevent duplicate sessions. Commands use event UUIDs and expected revisions with a session row lock. An identical event replays its acknowledgement; changed payloads or stale revisions are rejected. The player retains a failed selection, retries the same command UUID, and presents an explicit reload action for competing-tab updates. Cloud saves use session cookies and the publishable key, without administrative credentials.

Expected Server Action failures use a typed success/error envelope, so production React error redaction cannot hide revision conflicts or preflight IDs. Network failures retain the pending command and show a retry action.

Browser trials persist separately in IndexedDB `hanziflow.practice.v1`. Preparation occurs server-side using the local catalogue, followed by batches of 50 private trial snapshots; active rendering reads 25 at a time. A short-lived preparation cache holds no user answers. A ready local session survives reload/server restart. Trial keys are locally inspectable, as expected for an unauthenticated browser trial; cloud exam keys remain private. Trial progress is never uploaded to a cloud account.

## Data limitation

The existing Vietnamese gloss for `hsk30-b79-0367` (茶馆儿) contains punctuation placeholders rather than a meaning. A Vietnamese selection containing this entry is rejected with its ID; entries are not silently dropped. English complete Band 7–9 contains all 5,636 questions. No lexical content was changed by this feature. Correct the source translation through the separately reviewed enrichment workflow before expecting Vietnamese complete Band 7–9 to pass preflight.

## Reproduce validation

- `npm test`, `npm run typecheck`, `npm run lint`, `npm run build`.
- `npm run test:e2e`: isolated local trial server on port 3100; core learning regression plus group snapshots, exam edits/reload, separate retries, stale tabs, keyboard controls, full 5,636-question download and responsive layouts.
- `npm run test:practice-database`: isolated PostgreSQL cluster at `.local-tests/postgres`, port 55432. Refuses any other data directory, seeds actual catalogue fixtures, creates/removes its own temporary database.
- `npm run test:practice-cloud`: authorized configured Supabase plus app on localhost:3000 (`PRACTICE_TEST_URL` overrides). Creates only disposable confirmed QA accounts and removes them in `finally`; tests exact 500/5,636 ID sets beyond the API's 1,000-row limit, key secrecy, RLS, two-device resume, failed saves/retry, conflicts, submission and difficult flags. Never logs credentials.
- `npm run test:practice-exercises-cloud`: authenticated read-only preview, new server-side recipe installation, matching retry/defer and independent-browser resume, listening playback gating, hidden exam breakdowns and service-role restrictions. Creates/removes only a marked disposable QA account. Listening speech is mocked; lexical data, login, Server Actions and database grading are real.
- Set `PRACTICE_FULL_EXERCISES=1` for that cloud script to also install and compare every ID of a mixed 5,636-word Band 7–9 session. `PRACTICE_TEST_URL` can target a local optimized production server.
